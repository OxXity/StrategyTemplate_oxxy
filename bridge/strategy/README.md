# Стратегия RoboCup SSL Div. C

Стратегия для команды из 3 роботов (вратарь + 2 полевых) со слабым дриблером. Главный принцип —
ноль своих фолов: каждое действие проходит через `guards.py`, роутер дополнительно проверяет цели и
ограничивает скорость сближения с соперниками.

## Архитектура

```
bridge/strategy/
  strategy.py      оркестратор: такт process(field), выбор розыгрыша по состоянию игры, guards, телеметрия
  params.py        все настраиваемые параметры (sim/real через sim_real)
  memory.py        межтактовая память: владение, ведение, двойное касание, таймеры, пас в полёте, лог ударов
  world.py         модель мира: прогноз мяча, время роботов, перехват (numpy), владение, гонка за мячом
  evaluation.py    оценки: удар, пас, точка открывания, безопасный вынос, допустимый угол захвата
  kick_model.py    напряжение <-> скорость мяча, потолок 2.6 м/с, адаптивная поправка
  guards.py        G-1…G-13: белый список действий, легальность целей, двойное касание, лимит ведения, удары
  context.py       TickContext - всё, что нужно ролям в такте
  debug_draw.py    отрисовка (не больше 60 примитивов) и телеметрия STRATEGY
  roles/           assignment (назначение ролей), goalkeeper, attacker, support, defender, common
  plays/           open_play, stop, kickoff, free_kick, penalty, ball_placement, debug_scenarios, sparring
bridge/router/
  actions/dribble_actions.py  BallCarryLimiter, HoldBall, DribbleTo, DribbleKick, TapForward
  legality.py                 легальность целей (поле с зоной выбега, штрафные, мяч) - без импорта стратегии
  safety.py                   ограничитель скорости сближения (G-9), Phase 2 роутера
```

Такт `Strategy.process(field)`: `WorldModel` → `update_memory` → `assign_roles` → розыгрыш по
`field.game_state` → `guards.apply` → отрисовка. В `SAFE_MODE=True` исключение в роли даёт безопасное
действие, исключение всего такта — `Stop` всем (сообщение не чаще раза в секунду).

## Роли

- **Вратарь** (`field.gk_id`): отражение удара на линии вратаря; подбор медленного мяча в штрафной с
  предориентацией наружу, пас Опорному или безопасный вынос (через 3 с — без ожидания, через 6 с — в любой
  допустимый угол); позиционирование по биссектрисе, выход на владеющего соперника, угадывание удара
  по корпусу соперника.
- **Нападающий**: перехват по прогнозу, приём, подбор с предориентацией. Если по линии подъезда можно
  сразу бить — удар «с касания» без удержания мяча. С мячом каждый такт сравнивает удар / пас / ведение,
  учитывает время поворота с мячом; под давлением — уход вбок/вперёд, откидка по свободному коридору,
  вынос в конусе допустимого поворота. Отбор у соперника, стоящего спиной; анти-толкание.
- **Опорный**: открывание в лучшую точку (удар + безопасность паса + свобода + продвижение − время),
  добивание на своей стороне от линии удара, опека или перекрытие удара, перехват паса соперника.
  Режим (открывание / оборона / страховка) держится не меньше 0.6 с.
- **Защитник** (только если полевых больше двух): вторая линия.

Роли полевых: Нападающий — минимальная стоимость захвата; гистерезис `ROLE_SWITCH_MARGIN`/`ROLE_MIN_HOLD`;
владеющий мячом и получатель паса — Нападающий; робот с запретом двойного касания — не Нападающий;
на наших стандартах исполнитель не меняется.

## Стандарты

| Состояние | Наш | Соперника |
|---|---|---|
| STOP | только `GoToPoint`, ≥ 0.66 м до мяча, расстановка под возобновление | — |
| KICKOFF | исполнитель в круге за мячом, пас Опорному на свою половину, `SetPieceKick` с дриблером 0 | все на своей половине вне круга |
| FREE_KICK | удар / пас / безопасный ввод, решение фиксируется у мяча, удар ≤ 4 с | «стенка», опека, вратарь закрывает остаток створа |
| PENALTY | «буллит»: ведение ≤ 500 мм, откидка, повторный захват, удар не позже 7 с | вратарь на линии до ввода, затем сокращает угол |
| BALL_PLACEMENT | по умолчанию мяч ставит судья; `AUTO_BALL_PLACEMENT=True` — авторазмещение | освобождаем «стадион» |

## Параметры и калибровка

Все числа — в `params.py`. Пара `sim_real(a, b)`: `a` — симулятор, `b` — реальные роботы.
Константы, нужные роутеру (`KEEP_BALL_DIST`, отступ от штрафной, зона выбега, ограничитель сближения),
лежат в `bridge/const.py` (роутер не импортирует стратегию) и продублированы ссылками в `params.py`.

Калибровка — состояние `DEBUG` (`DEBUG_MODE=True`, `DEBUG_GAME_STATE=DEBUG`) и `params.DEBUG_SCENARIO`:

| Сценарий | Что даёт | Куда записать |
|---|---|---|
| `KICK_CALIBRATION` | таблица «напряжение → скорость мяча», `BALL_DECEL` | `KICK_TABLE_SIM`/`KICK_TABLE_REAL`, `BALL_DECEL`, затем `KICK_TABLE_CALIBRATED=True` |
| `TURN_TEST` | максимальная ω без потерь мяча (10 из 10), рекомендация 70 % | `BALL_HOLD_MAX_ANG_SPEED`, `BALL_HOLD_MAX_ANG_ACC` |
| `DRIBBLE_TEST` | ведение по квадрату, проверка трекера и лимитов | `BALL_HOLD_MAX_SPEED_*`, `BALL_HOLD_MAX_ACC` |
| `PASS_TEST` | доля приёмов при разных скоростях прихода и дистанциях | `PASS_ARRIVAL_SPEED` |
| `SHOOT_TEST` | точность и скорость ударов по воротам | `KICK_ALIGN_TOL_SHOT`, проверка ≤ `BALL_SPEED_ALERT` |
| `GK_TEST` | вратарь против спарринга (`TWO_TEAMS_PLAYING=True`, `SPARRING_SECOND_TEAM=True`) | параметры `GK_*` |

До калибровки модель удара консервативна: считается, что `VOLTAGE_SHOOT` даёт 3 м/с, напряжение не выше
`VOLTAGE_SHOOT`, в телеметрии предупреждение.

Что калибровать на реальных роботах в первую очередь: `KICK_TABLE_REAL`, `BALL_DECEL`,
`BALL_HOLD_MAX_ANG_SPEED/ACC`, `BALL_HOLD_MAX_SPEED_*`, `BALL_HOLD_MAX_ACC`, `PASS_ARRIVAL_SPEED`,
`ENEMY_MAX_SPEED/ACC`, `ENEMY_REACTION_TIME`, `SHOT_MIN_P`, `USE_KICK_FORWARD` (если автоудар не срабатывает
при прижатом мяче), `DRIBBLER_OFF_BEFORE_KICK`, `FIELD_OUT_MARGIN` (видит ли камера робота у края поля).

## Чек-лист перед матчем

1. В `.env`: `IS_SIMULATOR_USED=False`, `DEBUG_MODE=False` (Регламент 3.2.6 — автономность).
2. В `.env`: `COLOR`, `POLARITY`, `GK` (номер вратаря фиксируется до матча, п. 3.1), `ENEMY_GK`.
3. `TWO_TEAMS_PLAYING=False`.
4. В `params.py`: `SAFE_MODE=True`, `DEBUG_SCENARIO="NONE"`, `USE_CHIP_KICK=False`,
   `AUTO_BALL_PLACEMENT=False`, `KICK_ADAPTIVE` по решению команды.
5. Таблицы удара откалиброваны (`KICK_TABLE_CALIBRATED=True`), иначе удары слабее возможного.
6. `make test` проходит; в телеметрии STRATEGY нет строк `WARN` и `TICK FAILED` в первые секунды.

## Тесты

`make test` (pytest, ~3 с): смоук-тест всех состояний × активная команда × 5 расстановок × оба цвета;
удар, пас, модель удара, трекер ведения, двойное касание, роли, таймер вратаря, `BallCarryLimiter`,
`legal_target`, ограничитель сближения; сценарии в мини-симуляторе `tests/minisim.py` (штрафной, начальный
удар, пенальти, STOP, открытая игра против вратаря). Мини-симулятор упрощённый (кинематика, без
отскоков от бортов); он ловит логические регрессии, но не заменяет проверку в настоящем симуляторе.
